# Evidence Inbox v0.1 PRD

## 一句话定位

把用户主动提交的小红书公开内容，转换成“保留原始证据、明确待核验项、连接当前项目、给出下一步”的 Obsidian 收件箱。

## 用户问题

普通导入器解决“搬进来”，但不解决：

- 内容是否只是未经核验的社交平台观点；
- 它为什么与当前项目有关；
- 应连接到哪篇笔记；
- 收藏后下一步做什么；
- 更新来源时如何不覆盖用户自己的判断。

## v0.1 目标

1. 让新用户在 10 分钟内完成第一次公开链接导入；
2. 在任何 AI/图片失败时优先保住来源正文；
3. 同一来源重复导入保持一份，并保护用户内容；
4. 用三种差异化知识卡把“收藏”推进到“核验与行动”；
5. 保持法律、平台与安全边界可解释、可审计。

## 非目标

- 登录、Cookie、签名、验证码；
- 账号收藏/点赞/主页/专辑批量读取；
- 自动后台同步；
- 视频下载、OCR、转写；
- 付费授权服务器；
- 替用户断言社交平台内容已核验；
- 远程删除、点赞、评论、关注或私信。

## 核心用户流程

1. 用户粘贴分享文本或 1–10 条链接；
2. 插件按允许域名提取、批内去重；
3. 并发不超过 3 个地读取公开页面；
4. 预览标题、作者、摘要、图片、重复状态、受管更新/未受管冲突和目标路径；此时不得写 Vault；
5. 用户选择条目、知识卡、图片本地化、是否调用 AI；
6. 插件逐条执行，单条失败不终止批次；
7. 用户可取消活动批次；已完成条目保留，后续网络请求和写入停止；
8. 结果页显示 `created / updated / partial / skipped / failed`；
9. 多条或异常导入写入脱敏报告；
10. 用户进入知识卡或 `## 我的笔记` 补充判断与连接。

## 功能需求

### FR-1 输入

- 支持分享文本中的 URL；
- 支持 `xhslink.cn`、`xhslink.com`、小红书 `/explore` 与 `/discovery/item`；
- 一批最多 10 个唯一链接；
- 精确域名白名单，拒绝 lookalike host；
- 查询参数只用于本次请求，不能进入笔记、报告或日志。

### FR-2 预览

- 预览无 Vault 写入；
- 显示每条成功/失败与恢复建议；
- 显示重复来源与计划路径；
- 受管的重复来源默认可选，并明确只刷新来源区；没有管理标记的同源冲突默认排除。

### FR-3 来源解析

- 只解析 HTML 中的公开初始状态或 Open Graph 元数据；
- `JSON.parse` 数据，不执行页面 JavaScript；
- 没有公开笔记 ID 时必须失败；
- 主页、专辑、私密、删除和受限页面不能伪装成功。
- Initial State 与 OG/URL 中出现的来源 ID 必须一致；OG-only 回退标记为 `partial`。

### FR-4 持久化

- `evidence_source_id` 是唯一来源键；
- 文件名把来源 ID 放在截断标题之后，ID 永不被截断；
- 新笔记包含来源管理区、用户拥有的知识卡区与用户笔记区；
- 更新只替换来源管理区，并合并受管 frontmatter；知识卡区与用户笔记区逐字保留；
- 更新 frontmatter 时保留用户标签，并移除已失效的可选受管字段；
- 同源旧笔记没有标记时跳过，绝不全量覆盖。

### FR-5 图片

- 默认可选本地化；
- 只允许 HTTPS 小红书/XHS CDN 域名；
- 每一跳重定向重新校验允许域名，并拒绝非公开 DNS 地址、固定已验证地址；
- 校验 HTTP 状态、15 MB、MIME 与文件魔数；
- 稳定文件名支持失败后重试；
- 失败保留已移除查询参数的远程引用并标记 `partial`。

### FR-6 知识卡

- Raw Only 不产生知识卡；
- 三种模板都有共同字段：洞察、论点/依据、待核验、相关性、连接、30 分钟动作；
- 每种模板有独立业务字段；
- 无 AI 时生成可手填草稿；
- 知识卡创建后属于用户内容；普通重复导入不得覆盖，重新生成需要未来的显式操作；
- AI 输出必须标记待核验。

### FR-7 BYOK AI

- 默认关闭，不预设模型；
- 需要显式启用、Key、Base URL、模型；
- HTTPS 为默认要求，HTTP 仅限 loopback；
- 只发送当前来源文本与用户明确填写的上下文；
- AI 失败不得阻止来源归档；
- Key 使用 Obsidian SecretStorage，可立即清除，不进入插件 data.json、笔记、报告和诊断。

### FR-8 结果与报告

- 每条有稳定结果与原因；
- 一个失败不停止剩余条目；
- 取消或插件停用后不开始后续条目，活动页面/媒体请求使用取消信号；
- 结果可打开输出笔记；
- 多条或异常批次写脱敏报告；
- 失败项可重新放回输入阶段。

## 数据模型

### 来源事实

`EvidenceSource` 保存公开 ID、干净链接、标题、作者、正文、标签、公开时间、类型、图片和提取警告。

### 运行状态

- `capture_status`: 正文来源是否完整；
- `media_status`: 图片本地化是否完成；
- `ai_status`: AI 是否完成、失败、关闭或未请求；
- `knowledge_template`: 当前模板。

三个状态分开，避免“AI 失败”等于“来源归档失败”。

## 验收标准

- 支持范围内真实公开笔记导入成功率 ≥ 90%（30 条合法样本）；
- 可下载图片本地化成功率 ≥ 95%；
- 同一帖子连续导入三次只有一份来源笔记；
- 网络、图片或 AI 单条失败不影响同批其他项目；
- 更新原文时，知识卡区和用户笔记区逐字节保留；
- Cookie、API Key、查询参数、原始 HTML 不进入笔记或报告；
- 总体采集失败显示 `failed`，不能显示“成功 0 条”；
- README 足以让新用户 10 分钟内完成一次导入。

## 发布门槛

`0.1.0 beta` 之前必须完成：

1. 30 条合法样本矩阵；
2. 当前 Obsidian Desktop 手动 smoke test；
3. 至少一名非开发者按 README 独立安装；
4. 核对公开发布时的平台与内容授权边界；
5. 打包中只含 `main.js`、`manifest.json`、`styles.css`，不含 `data.json`。
